# 订单号生成器 - 监控与异步预加载功能说明

## 📋 功能概述

本次更新为订单号生成器添加了完整的监控系统和异步预加载机制，显著提升性能和稳定性。

---

## ✨ 新增功能

### 1️⃣ **双层阈值监控**

#### 📊 告警阈值（80%）
- 当号段使用率达到 **80%** 时，记录 INFO 级别日志
- 便于运维人员了解号段使用情况

#### 🚨 预警阈值（95%）
- 当号段使用率达到 **95%** 时，触发异步预加载
- 自动申请下一个号段，无需等待
- 确保订单生成不中断

---

### 2️⃣ **异步预加载机制**

```java
// 传统方式：等到用完才申请（有等待时间）
current > max → 同步申请 → 阻塞 → 返回

// 新方式：提前预加载（零等待）
usage >= 95% → 异步申请 → 缓存备用号段 → 用完无缝切换
```

**执行流程：**
```
1. 检测到使用率 >= 95%
   ↓
2. 启动异步任务 @Async
   ↓
3. 后台申请新号段
   ↓
4. 缓存到 nextRange
   ↓
5. 当前号段用完后，立即切换至备用号段
```

---

### 3️⃣ **实时监控信息**

调用 `getMonitorInfo()` 可查看：

```
号段监控 [bizTag=order]: 
  当前号段=[1,1000], 
  已使用=950/1000 (95.0%), 
  备用号段=有, 
  总请求=50000, 
  DB 请求=50, 
  DB 请求占比=0.10%
```

**监控指标：**
- ✅ 当前号段范围
- ✅ 已使用数量/总数量
- ✅ 使用率百分比
- ✅ 是否有备用号段
- ✅ 总请求次数
- ✅ 数据库请求次数
- ✅ DB 请求占比（性能关键指标）

## 🔧 核心代码解析

### **1. 检查并预加载方法**

```java
private void checkAndPreload() {
    if (start == 0 || max == 0) {
        return;
    }
    
    long used = current - start;           // 已使用数量
    long total = max - start + 1;          // 总数量
    double usageRate = (double) used / total;  // 使用率
    
    // 达到告警阈值（80%），记录日志
    if (usageRate >= LOG_THRESHOLD && usageRate < WARNING_THRESHOLD) {
        log.info("📊 号段使用率：{:.1f}% (当前={}/{})", 
                 usageRate * 100, used, total);
    }
    
    // 达到预警阈值（95%），触发异步预加载
    if (usageRate >= WARNING_THRESHOLD) {
        synchronized (asyncLock) {
            if (!isLoading && nextRange == null) {
                isLoading = true;
                log.info("🚨 号段使用率达到{:.1f}%，触发异步预加载", usageRate * 100);
                preloadNextSegmentAsync();
            }
        }
    }
}
```

**关键点：**
- ✅ 双重检查防止重复加载
- ✅ 同步锁保证线程安全
- ✅ 只在没有备用号段时才预加载

---

### **2. 异步预加载方法**

```java
@Async
public CompletableFuture<Void> preloadNextSegmentAsync() {
    try {
        log.info("开始异步申请新号段...");
        SegmentRange range = idSegmentService.nextSegment(ORDER_BIZ_TAG);
        
        synchronized (asyncLock) {
            if (nextRange == null) {
                nextRange = range;  // 缓存备用号段
                dbRequestCount.incrementAndGet();
                log.info("✅ 异步预加载成功，新号段：start={}, end={}, size={}", 
                         range.getStart(), range.getEnd(), 
                         (range.getEnd() - range.getStart() + 1));
            } else {
                log.info("⚠️ 已有备用号段，放弃本次预加载结果");
            }
            isLoading = false;
        }
    } catch (Exception e) {
        log.error("❌ 异步预加载号段失败", e);
        synchronized (asyncLock) {
            isLoading = false;
        }
    }
    return CompletableFuture.completedFuture(null);
}
```

**关键点：**
- ✅ `@Async` 注解实现异步执行
- ✅ 返回 `CompletableFuture` 支持链式调用
- ✅ 异常处理保证主流程不受影响
- ✅ 检查是否已有备用号段，避免浪费

### **3. 获取监控信息方法**

```java
public String getMonitorInfo() {
    long total = max - start + 1;
    long used = current - start;
    double usageRate = total > 0 ? (double) used / total : 0;
    
    return String.format(
        "号段监控 [bizTag=%s]: 当前号段=[%d,%d], 已使用=%d/%d (%.1f%%), " +
        "备用号段=%s, 总请求=%d, DB 请求=%d, DB 请求占比=%.2f%%",
        ORDER_BIZ_TAG,
        start,
        max,
        used,
        total,
        usageRate * 100,
        nextRange != null ? "有" : "无",
        totalRequestCount.get(),
        dbRequestCount.get(),
        totalRequestCount.get() > 0 ? 
            (double) dbRequestCount.get() / totalRequestCount.get() * 100 : 0
    );
}
```

## 🔍 故障排查

### **问题 1：异步预加载未触发**

**可能原因：**
- 未达到 95% 阈值
- 已有备用号段
- 异步线程池已满

**排查步骤：**
```bash
# 1. 查看日志
grep "号段使用率" application.log

# 2. 检查异步配置
grep "@Async" application.log

# 3. 查看监控信息
curl http://localhost:8080/admin/monitor/order-number
```

---

### **问题 2：DB 请求占比过高**

**正常情况：** < 0.2%（每 1000 单约 1 次 DB 请求）  
**异常情况：** > 1%

**可能原因：**
- 并发量太大，备用号段消耗快
- 异步预加载失败率高
- 号段步长设置过小

**解决方案：**
```yaml
# 增加号段步长
id:
  segment:
    step: 2000  # 默认 1000，可调整为 2000 或更大
```
