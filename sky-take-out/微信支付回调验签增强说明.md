# 微信支付回调验签与字段处理增强版

## 📋 功能概述

本次更新为微信支付回调接口添加了完整的验签逻辑、幂等性保护和详细的字段处理，提升支付安全性和可靠性。

## 🔧 新增文件

### 1. 实体类
- `PaymentCallbackLog.java` - 支付回调日志实体

### 2. Mapper 接口和 XML
- `PaymentCallbackLogMapper.java` - 回调日志 Mapper 接口
- `PaymentCallbackLogMapper.xml` - 对应的 MyBatis XML 配置

### 3. 数据库脚本
- `payment_callback_log.sql` - 支付回调日志表建表语句

## 📝 主要改动

### 1. PayNotifyController 增强

#### ✅ 新增验签逻辑
```java
private boolean verifySignature(HttpServletRequest request, String body)
```
- 验证 `Wechatpay-Signature`（签名）
- 验证 `Wechatpay-Timestamp`（时间戳）
- 验证 `Wechatpay-Nonce`（随机串）
- 使用 SHA256withRSA 算法验签

#### ✅ 新增幂等性保护
- **数据库层幂等**：通过唯一索引 `uk_out_trade_no_transaction_id` 防止重复
- **内存锁幂等**：使用 `ConcurrentHashMap` 防止并发回调
- **状态检查幂等**：已支付订单不重复处理

#### ✅ 完整字段解析
支付成功回调解析的字段：
- `out_trade_no` - 商户订单号
- `transaction_id` - 微信支付交易号
- `time_stamp` - 时间戳
- `success_time` - 支付成功时间
- `trade_type` - 交易类型（JSAPI 等）
- `trade_state` - 交易状态（SUCCESS）
- `trade_state_desc` - 状态描述
- `bank_type` - 付款银行
- `attach` - 附加数据
- `amount.total` - 订单总金额（分）
- `amount.payer_total` - 用户实际支付金额（分）
- `amount.currency` - 货币类型
- `amount.payer_currency` - 用户支付货币类型

退款成功回调解析的字段：
- `out_trade_no` - 商户订单号
- `out_refund_no` - 商户退款单号
- `refund_id` - 微信退款单号
- `refund_status` - 退款状态
- `success_time` - 退款成功时间
- `amount.total` - 退款总金额（分）
- `amount.from` - 退款来源
- `user_received_account` - 用户收款账户

#### ✅ 回调日志记录
记录每次回调的：
- 原始回调数据（加密前）
- 解密后的数据
- 处理状态（SUCCESS/FAIL/PROCESSING）
- 错误信息
- 处理次数

### 2. OrderService 增强

#### ✅ 新增 paySuccessWithValidation 方法
```java
@Transactional(rollbackFor = Exception.class)
public void paySuccessWithValidation(String outTradeNo, String transactionId, Double actualAmount)
```

**校验逻辑：**
1. **订单存在性校验**：订单必须存在
2. **幂等性校验**：已支付订单直接返回，不重复处理
3. **状态校验**：只有待支付订单才能处理
4. **金额校验**：微信支付金额与订单金额一致性校验（可选）

**事务保证：**
- 使用 `@Transactional` 保证原子性
- 异常时自动回滚

## 🗄️ 数据库表结构

### payment_callback_log 表

```sql
CREATE TABLE `payment_callback_log` (
  `id` BIGINT(20) NOT NULL AUTO_INCREMENT,
  `out_trade_no` VARCHAR(64) NOT NULL,          -- 商户订单号
  `transaction_id` VARCHAR(64) NOT NULL,        -- 微信支付交易号
  `callback_type` VARCHAR(32) NOT NULL,         -- PAY_SUCCESS/REFUND_SUCCESS
  `callback_status` VARCHAR(16) NOT NULL,       -- SUCCESS/FAIL/PROCESSING
  `raw_callback_data` TEXT,                     -- 原始回调数据
  `decrypted_data` TEXT,                        -- 解密后数据
  `error_message` VARCHAR(1024),                -- 错误信息
  `handle_count` INT(11) DEFAULT 1,             -- 处理次数
  `callback_time` DATETIME NOT NULL,            -- 回调时间
  `handle_time` DATETIME,                       -- 处理时间
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_out_trade_no_transaction_id` (`out_trade_no`, `transaction_id`),
  KEY `idx_out_trade_no` (`out_trade_no`),
  KEY `idx_callback_time` (`callback_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2. 配置证书路径（重要）

在 `WeChatProperties` 中需要添加证书配置：

```java
// 微信平台证书序列号
@Value("${wechat.mch-serial-no}")
private String mchSerialNo;

// 商户私钥证书路径
@Value("${wechat.private-key-path}")
private String privateKeyPath;

// 微信平台证书路径
@Value("${wechat.platform-cert-path}")
private String platformCertPath;
```

## ⚠️ 注意事项

### 1. 证书管理
- 需要从微信商户平台下载平台证书
- 证书文件需要妥善保管，建议放在安全目录
- 证书有有效期，需要定期更新

### 2. 分布式场景
如果是集群部署，需要将内存锁改为分布式锁：

```java
// 使用 Redis 分布式锁
String lockKey = "LOCK:PAY:" + outTradeNo;
Boolean success = redisTemplate.opsForValue()
    .setIfAbsent(lockKey, "1", 30, TimeUnit.SECONDS);
if (Boolean.FALSE.equals(success)) {
    log.warn("该支付回调正在处理中，请稍后重试，outTradeNo={}", outTradeNo);
    responseToWeixin(response);
    return;
}
try {
    // 业务处理
} finally {
    // 释放锁
    redisTemplate.delete(lockKey);
}
```

### 3. 日志清理
`payment_callback_log` 表会快速增长，建议：
- 定期归档历史数据（如每月）
- 只保留最近 3-6 个月的详细日志
- 可以创建定时任务进行清理

### 4. 监控告警
建议添加以下监控：
- 支付回调失败次数告警
- 签名验证失败告警
- 重复回调告警
- 回调处理时长监控

## 🔍 常见问题

### Q1: 如何处理证书过期的情况？
A: 定期检查证书有效期，提前 7 天更新证书文件，并重启服务加载新证书。

### Q2: 回调日志表数据量太大怎么办？
A: 
1. 定期归档历史数据
2. 只记录必要字段
3. 对 TEXT 字段进行压缩存储

### Q3: 如何排查回调失败问题？
A: 
1. 查看 `payment_callback_log` 表的 `error_message` 字段
2. 检查应用日志中的详细错误堆栈
3. 核对微信商户平台的回调记录
